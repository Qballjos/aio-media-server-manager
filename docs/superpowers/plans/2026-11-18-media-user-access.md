# Media-user access

1. Separate media-user sessions from administrator sessions. Keep existing admin, TV, and Homey authentication compatible. Test direct access to the catalog, application list, administrator homepage, and logs.
2. In Settings → Users, list and import accounts through the configured Seerr provider. Store grants against stable provider, server, and account identifiers. Expose only the fields needed by the UI. Use the provider sign-in flows below to verify account ownership before issuing a limited AIO session. Invalidate active sessions when the grant is revoked.
3. Serve member-specific search, own requests, Trending, and recently available media through member-authenticated endpoints. Derive requester identity from the session. Enforce Seerr permissions and quotas when submitting requests. Apply the existing Trending filter to all users. Resolve availability with the user's media-library permissions and sanitize errors and statuses that could reveal private library contents. Test with shared and private copies of the same title.
4. Add the member dashboard with Request limits and Support widgets, and Settings sections for profile, theme, and language. Use existing components and translation conventions. Verify desktop and mobile navigation, direct route access, and fallback states.
5. Link the Support widget to Settings → Support for member reports and replies. Scope member access to their own threads. Provide an administrator inbox with new-report counts, replies, and status changes. Verify cross-account isolation and both sides of the report flow.

## Media-account sign-in

- **Jellyfin Quick Connect.** Start Quick Connect on the configured Jellyfin server and show its temporary code in AIO. The user approves the code from an already signed-in Jellyfin client. Complete the exchange on the AIO backend and verify the returned Jellyfin server and account IDs. Show a clear state when Quick Connect is disabled or the code expires. [Jellyfin Quick Connect](https://jellyfin.org/docs/general/server/quick-connect/)
- **Plex PIN sign-in.** Start the official Plex PIN flow and send the user to Plex to approve the sign-in. Complete the exchange on the AIO backend and verify the Plex account ID. Match the account to the grant for the Plex server configured in Seerr and verify the account still has access to that server. [Plex developer documentation](https://developer.plex.tv/pms/)
- **AIO session.** Offer the sign-in option that matches Seerr’s configured source. Bind each short-lived attempt to the initiating browser and consume it once. Keep provider exchange secrets and tokens on the backend. Issue a limited AIO session only after matching the verified identity to an active grant. Return the user to AIO. Seerr handles account import and media requests.
- **Verification.** Test both providers independently, including successful approval, expiration, replay, completion from a different browser, an account without a grant, and revocation. Confirm that a limited session cannot access the catalog or other administrator APIs.
